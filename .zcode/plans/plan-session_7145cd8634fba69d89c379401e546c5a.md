
# LokaQuest — Full Implementation Plan

## TL;DR
Build a complete, deployable Next.js + Phaser + Supabase cultural learning game in **6 production phases**, starting from an empty repo.

---

## Phase 1 — Foundation & Project Scaffold
**Goal:** Working Next.js app with Supabase configured, deployable to Vercel.

1. Initialize Next.js (App Router, TypeScript, Tailwind CSS).
2. Install and configure dependencies: `@supabase/ssr`, `phaser`, `zod`, `react-hook-form`, `lucide-react`.
3. Create folder structure per the master prompt.
4. Set up Supabase clients (`lib/supabase/client.ts` for browser, `lib/supabase/server.ts` for server).
5. Create `.env.example`, `.gitignore`, `vercel.json`, `next.config.ts`.
6. Create `docs/deployment-vercel.md`.
7. Verify `next build` succeeds locally.

**Deliverable:** Scaffolded project that builds without errors.

---

## Phase 2 — Database, Auth & API Layer
**Goal:** Persistent backend with authentication and versioned API.

1. Write Supabase SQL migrations for all tables (profiles, cultural_regions, cultural_contents, missions, mission_questions, mission_attempts, mission_answers, player_progress, achievements, user_achievements, cultural_artifacts, user_artifacts, learning_assessments, assessment_responses, educator_groups, educator_group_members, audit_logs).
2. Enable RLS on all tables with proper policies.
3. Create `supabase/seed.sql` with demo content (3 regions, 3 missions, sample questions, achievements).
4. Implement auth pages: login, register, forgot-password, callback.
5. Implement server-side auth utilities using `@supabase/ssr`.
6. Create API routes under `app/api/v1/` for profile, regions, missions, attempts, progress, achievements, assessments.
7. Add Zod validation schemas for all API inputs.
8. Add protected route middleware.

**Deliverable:** Working auth flow, protected APIs, and database schema.

---

## Phase 3 — Core Gameplay & UI
**Goal:** Playable cultural exploration with 3 complete mini-games.

1. Build landing page with branding, featured missions, and CTAs.
2. Build exploration map page showing 3 cultural regions.
3. Build region detail pages with cultural content.
4. Build mission hub and progress tracking UI.
5. Implement **Mission 1 — Batik Detective**: pattern-matching game with cultural explanations.
6. Implement **Mission 2 — Gamelan Maestro**: instrument identification with audio feedback.
7. Implement **Mission 3 — Wayang Story Adventure**: story sequencing and character identification.
8. Integrate Phaser 3 with Next.js (dynamic import, client-only, proper cleanup).
9. Implement server-validated scoring and XP rewards.
10. Add achievement system with badges.

**Deliverable:** All 3 mini-games are playable end-to-end with persisted progress.

---

## Phase 4 — Dashboards & Learning
**Goal:** Educator and admin experiences with assessments.

1. Build player dashboard (progress, achievements, artifacts).
2. Build pre-test and post-test assessment flow.
3. Build educator dashboard (learner progress, assessment results).
4. Build admin dashboard (content management, user/role management, audit logs).
5. Implement content CRUD APIs with draft/review/published/archived states.
6. Enforce role-based access on all protected routes and APIs.

**Deliverable:** Full management and learning assessment features.

---

## Phase 5 — Testing, Security & Polish
**Goal:** Production-ready quality.

1. Write unit tests for business logic and API validation.
2. Write integration tests for auth and API endpoints.
3. Add E2E test for critical user journey (register → play mission → verify persistence).
4. Run security audit: verify RLS policies, no exposed secrets, proper auth checks.
5. Test mobile responsiveness and Phaser touch controls.
6. Optimize bundle size (lazy load Phaser, compress assets).
7. Add loading states, error boundaries, and fallback experiences.

**Deliverable:** Passing tests, security audit passed, polished UX.

---

## Phase 6 — CI/CD & Deployment
**Goal:** Live, publicly accessible production deployment.

1. Configure GitHub Actions for CI (lint, typecheck, test, build).
2. Set up Vercel project with GitHub integration.
3. Configure Vercel environment variables (Preview + Production).
4. Apply database migrations to production Supabase.
5. Deploy to Vercel and verify:
   - Landing page loads
   - Registration/login works
   - All 3 missions are playable
   - Scores persist after reload
   - Educator and admin dashboards enforce permissions
6. Write final deployment documentation.
7. Provide actual public URL and handoff.

**Deliverable:** Live production deployment with verified functionality.

---

## Key Technical Decisions
- **Single Next.js repo** — no separate backend service
- **Supabase PostgreSQL** with RLS for all data access
- **Phaser 3** dynamically imported in client components
- **Zod** for all input validation
- **Tailwind CSS** for styling
- **TypeScript strict mode** throughout

## Risks & Mitigations
- **Phaser + Next.js SSR conflicts:** Use `next/dynamic` with `ssr: false`
- **Vercel Function timeout:** Keep API handlers lean, use transactions
- **Asset loading:** Lazy-load game assets, provide fallbacks
- **RLS complexity:** Test policies thoroughly in Phase 5

## Estimated Scope
~80–120 files across all phases. Each phase builds on the previous one.
