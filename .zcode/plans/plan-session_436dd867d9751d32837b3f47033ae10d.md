## Rencana implementasi Ensiklopedia Budaya Nusantara

Modul akan ditambahkan ke LokaQuest yang ada, memakai Next.js 15, TypeScript, Tailwind, Supabase, autentikasi, wilayah, sumber, dan misi yang sudah tersedia. Skema database bersifat additive: tidak menghapus/mengubah data game atau pengguna.

### 1. Database, peran, dan RLS
- Tambahkan migration baru untuk kategori, artikel terstruktur, relasi artikel-wilayah, referensi, media, artikel terkait, bookmark, koleksi pribadi, riwayat baca, contributor/editor, review, revisi, dan relasi misi/kuis yang relevan.
- Gunakan `cultural_regions`, `cultural_sources`, `missions`, dan `profiles` yang sudah ada; tidak membuat entitas duplikat.
- Artikel memiliki slug unik dan status editorial `draft → review → approved → published → archived`. Tambahkan indeks filter/pagination dan full-text search PostgreSQL.
- Terapkan RLS: hanya artikel/media terbit yang terlihat publik, data pribadi hanya terlihat pemiliknya, dan kewenangan editorial diverifikasi server-side. Akun yang ada hanya mengenal `player/educator/admin`; izin editor/reviewer/contributor akan berada pada tabel terpisah agar tidak perlu memperlebar constraint role profil.
- Migration memperhatikan bahwa skema live memiliki `image_source_id` yang tidak tercatat di migration lama; fitur baru tidak akan bergantung pada drift tersebut.

### 2. API dan pencarian
- Buat API publik versi `/api/v1/encyclopedia` untuk daftar/detail artikel, kategori, wilayah, pencarian, koleksi dan bookmark.
- Buat API admin/editor untuk pembuatan/perubahan artikel, alur review/publikasi, pengelolaan media dan relasi; cek izin di server, validasi dengan Zod, gunakan pagination dan response envelope yang konsisten, serta catat perubahan penting ke `audit_logs`.
- Pencarian dan filter dijalankan di Postgres, bukan dengan memuat seluruh konten ke browser. Draft/unpublished tidak pernah dikembalikan oleh query publik.

### 3. Halaman publik dan pengalaman pengguna
- Implementasikan `/encyclopedia`, `/encyclopedia/explore`, `/encyclopedia/regions`, `/encyclopedia/categories`, `/encyclopedia/[slug]`, `/encyclopedia/collections`, `/encyclopedia/favorites`, dan `/encyclopedia/search`.
- Ikuti pola desain LokaQuest: bahasa Indonesia, token warna semantik, `Card`, `EmptyState`, `Skeleton`, `Reveal`, `font-display`, tata letak responsif dan status loading/error/empty yang aksesibel.
- Halaman artikel bergaya editorial: latar dan konteks budaya, bagian isi terstruktur, galeri, referensi dan atribusi lisensi, artikel terkait, mekanisme koreksi/masukan, serta misi terkait bila ada. Artikel publik tidak memerlukan login.
- Bookmark, koleksi, dan riwayat baca memerlukan login; pengguna memiliki kontrol atas riwayatnya.

### 4. CMS dan integrasi game
- Tambahkan CMS pada admin untuk mengelola artikel, kategori, sumber, atribusi media, preview, draft, review, persetujuan, publikasi, arsip dan audit.
- Role contributor tidak dapat mempublikasikan; admin/editor/reviewer memiliki batas kewenangan eksplisit. Hubungkan misi yang sudah ada berdasarkan ID, tanpa mewajibkan setiap artikel mempunyai misi.
- Gunakan Supabase Storage untuk upload yang diizinkan dengan metadata hak/lisensi dan kebijakan bucket terdokumentasi. Aset eksternal tetap memakai atribusi yang benar; tidak mengunggah ulang materi berhak cipta.

### 5. SEO, pengujian, dokumentasi
- Tambahkan metadata unik, canonical/OG, structured data yang sesuai, sitemap dan robots; hanya artikel terbit yang boleh terindeks. Atur cache/revalidasi untuk konten publik dan cegah caching data pengguna/admin.
- Tambahkan pengujian validasi, pencarian/filter, privasi draft, RLS/otorisasi, workflow publikasi, bookmark, atribusi, tautan misi dan invalidasi cache.
- Perbarui dokumentasi schema, endpoint, proses editorial, Storage, cache dan deployment. Verifikasi dengan lint, typecheck, test dan production build.

### Tahapan dan batas keselamatan
1. Migration, policy/RLS, tipe dan validasi.
2. API publik/search beserta halaman discovery dan artikel.
3. Bookmark/koleksi/riwayat dan relasi misi.
4. API admin dan CMS/workflow/media.
5. SEO, tes, dokumentasi, lalu build.

Saya tidak akan menjalankan migration pada Supabase produksi, mereset database, mengubah bucket produksi, atau melakukan deployment tanpa persetujuan khusus. Data budaya baru tidak akan dikarang; seed hanya untuk kategori dasar atau konten yang memiliki sumber terverifikasi.
